Aula 1 · 15 min

A máquina com agentes: quem faz o quê e onde você decide

Agente de IA é bom no repetitivo: pesquisar, rascunhar, conferir, avisar, relatar. É ruim em decidir o que vale publicar. A máquina do método inemaSEO separa as duas coisas: os agentes trabalham em linha, e dois portões param tudo até você aprovar.

Começar a aula

Nesta aula você vai

  1. 1As sete funções da máquina, do pesquisador ao observador
  2. 2Onde ficam os dois portões e quanto tempo eles custam
  3. 3Por que tudo roda pela assinatura, e não por API
  4. 4O AGENTS.md: as regras que o agente lê antes de começar

Objetivo: montar a linha pesquisador → observador com dois portões humanos e um AGENTS.md que diz o que o agente nunca faz sozinho.

02 · Como a máquina roda na prática

Clique em cada passo.

1. Pela assinatura

O método manda rodar o modelo pela assinatura (Claude Code ou Codex CLI) sempre que possível. Chamada de API paga só com autorização explícita para aquela finalidade.

Assim o custo é previsível e nenhuma chave vira atalho para o agente gastar sozinho.

2. Um agente, várias funções

As sete funções podem ser o mesmo agente, com pedidos diferentes. O que importa é a ordem e os portões, não quantos programas rodam.

Comece com uma função só (o auditor, na aula 2) e acrescente as outras quando a anterior estiver confiável.

3. O portão é parada de verdade

Portão não é "o agente avisa e segue". O agente para, entrega o que fez e só continua depois do seu sim.

No INEMA, os rascunhos dos pilares 2 e 3 ficaram parados no portão 2 (cerca de 3.150 e 2.450 palavras) e só foram publicados em 24/09, depois da revisão.

Regra que funcionaTudo que sai do site (push, aviso a buscador, e-mail) ou que gasta dinheiro passa por um portão.

4. O AGENTS.md

Claude Code e Codex leem um arquivo de instruções na raiz do projeto antes de trabalhar (o Claude Code lê o CLAUDE.md; o Codex, o AGENTS.md). Escreva ali o que o agente faz, o que ele nunca faz sozinho e como trabalha em lote.

Cada falha corrigida vira uma regra nova nesse arquivo. A aula 8 mostra as falhas reais que viraram regra.

03 · A máquina e o AGENTS.md do seu projeto de SEO

Copie a máquina para o README do projeto e o AGENTS.md para a raiz. Troque o que está entre os sinais de menor e maior.

A máquina (docs/METODO.md do inemaSEO)
Humano escolhe o tema do mês
 ├─ Pesquisador   → lista de palavras-chave com score (autocomplete, Trends, Search Console, SERP)
 ├─ Oportunidade  → 5–10 GO com a URL e o ativo real que dá o dado próprio
 │   GATE 1: humano aprova a lista
 ├─ Briefing      → intenção, lacunas do top 10, dado próprio obrigatório, links internos, escada
 ├─ Redator       → rascunho que lê o repositório/a transcrição do ativo real
 ├─ QA            → checklist (docs/CHECKLIST.md) + testes + escada de links
 │   GATE 2: humano revisa (10–20 min por página)
 ├─ Publicador    → commit + push, aviso aos buscadores, checagem pós-deploy
 └─ Observador    → export semanal, o que subiu, o que travou → volta ao GATE 1
AGENTS.md (modelo; no Claude Code, o mesmo texto vai no CLAUDE.md)
# AGENTS.md — SEO de <seusite.com>

## O que você faz
- Pesquisa, briefing, rascunho, QA (docs/CHECKLIST.md) e relatório semanal.
- Tudo pela assinatura (Claude Code ou Codex). Nada de API sem autorização.

## O que você nunca faz sozinho (pare e pergunte)
- Chamar API (Search Console, Bing, IndexNow, modelos) sem autorização escrita para aquela finalidade.
- Commit + push de página nova: só depois do PORTÃO 2 (eu reviso cada página).
- Apagar página, arquivo ou URL que já foi indexada.
- Afirmar que algo não existe sem conferir (ex.: Search Console: olhe o TXT do DNS antes).

## Como você trabalha
- Lote: dry-run primeiro; marcador para não duplicar; pule repositório com alteração não commitada.
- Texto a partir de fonte: só fatos da fonte. Item que falha na trava é descartado, não consertado.
- Outra sessão pode mexer no mesmo repo: commite só os seus arquivos; git pull --rebase --autostash antes do push.
- Segredo fica no .env (que está no .gitignore). Aqui vai só o NOME da variável.
- Falha corrigida vira uma linha em FALHAS.md: data | o que quebrou | menor correção | prompt ou infra.
Simulação: exemplo ilustrativo
  • Você: tema do mês, portão 1 (lista), portão 2 (cada página), qualquer gasto ou API.
  • Agente: pesquisa, pontuação, briefing, rascunho, checklist, commit preparado, export e relatório.
  • Script: o que precisa ser igual sempre (auditoria, trava, aviso só com URL 200, link de volta com marcador).
  1. Auditor (aula 2)
  2. Extração com trava (aula 3)
  3. Lote seguro (aula 4)
  4. Meta verificável e portão (aula 5)
  5. Observador: relatório semanal (aula 6)

Uma função de cada vez, só depois de a anterior ficar confiável.

04 · Prática: a sua máquina no papel

Use o seu site ou um site de teste.

E1 · O AGENTS.md do projeto

30 min

Crie a pasta do projeto de SEO, copie o modelo de AGENTS.md (ou CLAUDE.md) e adapte ao seu site. Abra o Claude Code ou o Codex na pasta e pergunte: "quais ações você não pode fazer sem me perguntar?".

Pronto quando: o arquivo está na raiz do projeto e o agente responde citando pelo menos as regras de API, de push e de apagar.

E2 · Uma volta no papel

25 min

Escolha um tema do mês e escreva, para cada função da máquina, o que ela entrega e onde o resultado fica (arquivo, pasta, planilha).

Pronto quando: você tem as sete funções com a entrega de cada uma, e os dois portões marcados com quem aprova e em que arquivo a aprovação fica registrada.
