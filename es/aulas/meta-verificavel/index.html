Clase 5 · 17 min

Meta verificable en loop y la compuerta antes del push

"Deja la página bien" no es una meta: el agente decide solo que terminó. Una meta verificable es un comando con la salida esperada, y un control que impide cumplirla por atajo. El agente corre en loop hasta que pase. Después, lo que ningún comando prueba (dato propio, voz, utilidad) queda para la compuerta humana, antes del push.

Comenzar la lección

En esta lección vas a

  1. 1La escala de 0 a 4: de meta vaga a meta protegida
  2. 2Función, regresión y límite: las tres capas del listo
  3. 3Lo que el comando prueba y lo que solo tú pruebas
  4. 4El loop hasta pasar y la parada en la compuerta

Objetivo: escribir la meta del agente como comando → salida esperada, con control contra atajos, y hacer push solo después de la compuerta humana.

02 · Cómo escribir la meta

Toca cada paso.

1. Las cinco preguntas

¿Se puede comprobar con un comando? ¿La respuesta es sí o no? ¿Es imposible cumplir sin hacer el trabajo? ¿La prueba aparece en la salida? ¿Función, regresión y límite están cubiertos?

Son las preguntas de la plantilla goal.md del kit Execução Longa (kit de ejecución larga) (abierto, de INEMA).

2. Tres capas

Función: la página hace lo que debía (un H1, canónico correcto, JSON-LD presente). Regresión: el resto del sitio no se rompió (pruebas y build). Límite: el agente no tocó donde no debía.

En el portal de INEMA, la regla es ejecutar las pruebas y el build antes del push: el main ya se rompió por causa de una traducción.

3. Lo que va a la compuerta

De la checklist de los 16, una parte es mecánica (un H1, título de 50 a 60 caracteres, enlaces que responden 200, JSON-LD válido) y se vuelve comando.

Otra parte es criterio: dato propio verificable, lectura humana, prueba del cambio. Esa va a la compuerta 2, de 10 a 20 minutos por página.

4. El loop

Codex y Claude Code tienen el comando /goal: el agente trabaja hasta que la condición aparezca cumplida en la salida. En Claude Code, el evaluador solo lee la conversación, así que la prueba tiene que imprimirse.

Detente e interviene si hay 3 ciclos sin avance o si el agente reabre un ítem ya hecho.

03 · Una meta de nivel 3 para una página nueva

Cambia las rutas por las de tu proyecto. Lo que está entre signos de menor y mayor es para completar.

goal.md (adaptado del kit Execução Longa)
# Goal — página nueva: <slug>

## Resultado
La página /<slug>/ lista para la compuerta 2, sin romper el resto del sitio.

## Criterios de listo (comando → salida esperada)
**Función**
- [ ] grep -c '<h1' dist/<slug>/index.html → 1
- [ ] grep -o 'rel="canonical" href="[^"]*"' dist/<slug>/index.html → https://www.seusite.com/<slug>/
- [ ] grep -c 'application/ld+json' dist/<slug>/index.html → 1 o más

**Regresión**
- [ ] npm test && npm run build → sin error

**Límite**
- [ ] git diff --stat -- tests/ docs/CHECKLIST.md → vacío
- [ ] git status --porcelain → solo la página nueva y las 2–3 páginas de la escalera de enlaces

## Compuerta humana (el comando no lo prueba)
- dato propio con enlace a la evidencia (checklist 2)
- lectura humana: opinión, qué salió mal, voz del autor (checklist 9)
- prueba del cambio (checklist 10)

## Restricciones
- solo por la suscripción; nada de API sin autorización
- sin push: el push es mío, después de la compuerta
Pedido de loop (/goal en Claude Code)
/goal La salida del terminal muestra cada comando del goal.md con la salida esperada, y el goal.md tiene todos los criterios marcados. No hagas push. Al terminar, detente y muéstrame el diff.
Simulación: ejemplo ilustrativo
  • 0 vago: "mejora la página nueva".
  • 1 subjetivo: "página revisada y limpia" (el agente se aprueba a sí mismo).
  • 2 burlable: "build con 0 fallas" (se puede borrar la prueba).
  • 3 protegido: build sin error y pruebas intactas y un H1 y canónico igual a la URL.
  • 4 independiente: nivel 3 + tú en la compuerta 2 leyendo como lector.
  • Palabras como bueno, limpio, adecuado, completo.
  • Depende de que el agente diga que terminó.
  • Solo conteo, sin revisar el contenido.
  • No dice qué no se puede cambiar.

04 · Práctica: una página por el loop y por la compuerta

Usa una página nueva (o una reescrita) de tu sitio.

E1 · El goal.md

30 min

Escribe el goal.md de la página con al menos un criterio de función, uno de regresión y uno de límite, y pasa las cinco preguntas en cada uno.

Listo cuando: cada criterio tiene un comando y la salida esperada, hay al menos un control (archivo congelado o conteo con contenido) y la sección de compuerta humana lista lo que el comando no prueba.

E2 · Loop y compuerta

40 min

Ejecuta el agente con el pedido de loop. Cuando se detenga, lee la página como lector, decide y solo entonces haz tú mismo el push.

Listo cuando: la conversación muestra cada comando con la salida esperada, el goal.md tiene tu aprobación de la compuerta 2 con fecha, y el push salió después de ella.
