Clase 1 · 15 min

La máquina con agentes: quién hace qué y dónde decides tú

El agente de IA es bueno en lo repetitivo: investigar, redactar borradores, revisar, avisar, informar. Es malo para decidir qué vale la pena publicar. La máquina del método inemaSEO separa las dos cosas: los agentes trabajan en línea, y dos compuertas lo detienen todo hasta que tú apruebes.

Comenzar la lección

En esta lección vas a

  1. 1Las siete funciones de la máquina, del investigador al observador
  2. 2Dónde están las dos compuertas y cuánto tiempo cuestan
  3. 3Por qué todo corre por la suscripción y no por API
  4. 4El AGENTS.md: las reglas que el agente lee antes de empezar

Objetivo: armar la línea investigador → observador con dos compuertas humanas y un AGENTS.md que dice qué nunca hace el agente por su cuenta.

02 · Cómo corre la máquina en la práctica

Toca cada paso.

1. Por la suscripción

El método manda correr el modelo por la suscripción (Claude Code o Codex CLI) siempre que se pueda. Llamada de API de pago solo con autorización explícita para esa finalidad.

Así el costo es predecible y ninguna clave se convierte en atajo para que el agente gaste por su cuenta.

2. Un agente, varias funciones

Las siete funciones pueden ser el mismo agente, con pedidos distintos. Lo que importa es el orden y las compuertas, no cuántos programas corren.

Empieza con una sola función (el auditor, en la clase 2) y agrega las otras cuando la anterior sea confiable.

3. La compuerta es una parada de verdad

Una compuerta no es "el agente avisa y sigue". El agente se detiene, entrega lo que hizo y solo continúa después de tu sí.

En INEMA, los borradores de los pilares 2 y 3 quedaron detenidos en la compuerta 2 (cerca de 3.150 y 2.450 palabras) y solo se publicaron el 24/09, después de la revisión.

Regla que funcionaTodo lo que sale del sitio (push, aviso a un buscador, correo) o que gasta dinero pasa por una compuerta.

4. El AGENTS.md

Claude Code y Codex leen un archivo de instrucciones en la raíz del proyecto antes de trabajar (Claude Code lee el CLAUDE.md; Codex, el AGENTS.md). Escribe ahí lo que el agente hace, lo que nunca hace por su cuenta y cómo trabaja en lote.

Cada falla corregida se convierte en una regla nueva en ese archivo. La clase 8 muestra las fallas reales que se volvieron regla.

03 · La máquina y el AGENTS.md de tu proyecto de SEO

Copia la máquina al README del proyecto y el AGENTS.md a la raíz. Cambia lo que está entre los signos de menor y mayor.

La máquina (docs/METODO.md de inemaSEO)
El humano elige el tema del mes
 ├─ Investigador  → lista de palabras clave con score (autocomplete, Trends, Search Console, SERP)
 ├─ Oportunidad   → 5–10 GO con la URL y el activo real que da el dato propio
 │   GATE 1: el humano aprueba la lista
 ├─ Briefing      → intención, vacíos del top 10, dato propio obligatorio, enlaces internos, escalera
 ├─ Redactor      → borrador que lee el repositorio/la transcripción del activo real
 ├─ QA            → checklist (docs/CHECKLIST.md) + pruebas + escalera de enlaces
 │   GATE 2: el humano revisa (10–20 min por página)
 ├─ Publicador    → commit + push, aviso a los buscadores, verificación posdeploy
 └─ Observador    → export semanal, qué subió, qué se trabó → vuelve al GATE 1
AGENTS.md (modelo; en Claude Code, el mismo texto va en el CLAUDE.md)
# AGENTS.md — SEO de <seusite.com>

## Qué haces
- Investigación, briefing, borrador, QA (docs/CHECKLIST.md) e informe semanal.
- Todo por la suscripción (Claude Code o Codex). Nada de API sin autorización.

## Lo que nunca haces solo (detente y pregunta)
- Llamar a una API (Search Console, Bing, IndexNow, modelos) sin autorización escrita para esa finalidad.
- Commit + push de una página nueva: solo después de la COMPUERTA 2 (yo reviso cada página).
- Borrar una página, archivo o URL que ya fue indexada.
- Afirmar que algo no existe sin comprobarlo (ej.: Search Console: mira primero el TXT del DNS).

## Cómo trabajas
- Lote: dry-run primero; marcador para no duplicar; salta el repositorio con cambios sin commitear.
- Texto a partir de una fuente: solo hechos de la fuente. El ítem que falla en el control se descarta, no se arregla.
- Otra sesión puede tocar el mismo repo: haz commit solo de tus archivos; git pull --rebase --autostash antes del push.
- El secreto va en el .env (que está en el .gitignore). Aquí va solo el NOMBRE de la variable.
- Una falla corregida se vuelve una línea en FALHAS.md: fecha | qué se rompió | corrección mínima | prompt o infra.
Simulación: ejemplo ilustrativo
  • Tú: tema del mes, compuerta 1 (lista), compuerta 2 (cada página), cualquier gasto o API.
  • Agente: investigación, puntuación, briefing, borrador, checklist, commit preparado, export e informe.
  • Script: lo que necesita ser igual siempre (auditoría, control, aviso solo con URL 200, enlace de vuelta con marcador).

  2. Extracción con control (clase 3)

Una función a la vez, solo después de que la anterior sea confiable.

04 · Práctica: tu máquina en papel

Usa tu sitio o un sitio de prueba.

E1 · El AGENTS.md del proyecto

30 min

Crea la carpeta del proyecto de SEO, copia el modelo de AGENTS.md (o CLAUDE.md) y adáptalo a tu sitio. Abre Claude Code o Codex en la carpeta y pregunta: "¿qué acciones no puedes hacer sin preguntarme?".

Listo cuando: el archivo está en la raíz del proyecto y el agente responde citando al menos las reglas de API, de push y de borrar.

25 min

Listo cuando: tienes las siete funciones con la entrega de cada una, y las dos compuertas marcadas con quién aprueba y en qué archivo queda registrada la aprobación.
