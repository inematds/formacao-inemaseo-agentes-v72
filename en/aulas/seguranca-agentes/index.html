Lesson 8 · 20 min

What went wrong with agents and the security rules

Agents fail in predictable ways: they claim without checking, add up wrong, break what was working, use the key they found. Each real failure in INEMA's SEO project became one line in the failure log and one rule in AGENTS.md. This lesson shows the failures, the smallest fix for each, and closes the course with your plan.

02 · The real failures of the INEMA SEO project

Tap each step. All of them are in the project's FALHAS.md.

1. Claimed without checking

A plan made by an agent said the site had no Search Console: it looked only in the code. The fix was to check the DNS TXT record before claiming it was missing.

The same day, the agent suggested installing a package for a different processor than the machine's. Rule: check the architecture before suggesting a package.

2. Added up wrong

The weekly export added up the brand's impressions by the query + page combination, and the part became larger than the total. The fix was to add up by query only.

Another script counted as enriched every listing page present in the file, without reading the field that said whether it was. In both cases: an impossible number that a simple check would catch.

3. Broke what worked

A visual change left the course index as "search only," and the 310 listing pages lost their only internal link in the server HTML. The fix was a collapsed index, with no visual change.

Regenerating an area of the site with an old generator would undo a canonical fix made by hand. The rule was written down: don't regenerate over it.

4. Key, API, and notice

The first IndexNow submission with a newly published key came back 403; resubmitting a few minutes later fixed it (infra). The IndexNow key is public by design; the Bing Webmaster one is a secret.

The method's rule: paid API only with explicit authorization for that purpose, and notifying search engines only with URLs that return 200.

Test repository built for the lesson; the key is fake.

  • .env ignored: the file with the keys doesn't go into the commit.
  • avisar.sh: uses $BING_API_KEY, a reference to the variable. That's correct.
  • rodar.sh: has the key's value written in it. Leak: take it out of the file, change the key in the dashboard, and treat it as exposed.
