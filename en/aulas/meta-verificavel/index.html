Lesson 5 · 17 min

Verifiable goal in a loop, and the gate before the push

"Make the page good" is not a goal: the agent decides on its own that it is done. A verifiable goal is a command with the expected output, plus a check that stops it from being met by a shortcut. The agent runs in a loop until it passes. After that, what no command can prove (first-hand data, voice, usefulness) is left for the human gate, before the push.

02 · How to write the goal

Tap each step.

1. The five questions

Can you check it with a command? Is the answer yes or no? Is it impossible to meet without doing the work? Does the proof appear in the output? Are function, regression and limit covered?

These are the questions from the goal.md template in the Execução Longa (Long Run kit) (open, from INEMA).

2. Three layers

Function: the page does what it should (one H1, right canonical, JSON-LD present). Regression: the rest of the site didn't break (tests and build). Limit: the agent didn't touch where it shouldn't.

On the INEMA portal, the rule is to run the tests and the build before the push: main has already broken because of a translation.

3. What goes to the gate

Of the 16-item checklist, part is mechanical (one H1, title of 50 to 60 characters, links that return 200, valid JSON-LD) and becomes a command.

Another part is judgment: verifiable first-hand data, human reading, swap test. That goes to gate 2, 10 to 20 minutes per page.

4. The loop

Codex and Claude Code have the /goal command: the agent works until the condition shows as met in the output. In Claude Code, the evaluator only reads the conversation, so the proof has to be printed.

Stop and step in if there are 3 cycles with no progress or if the agent reopens an item that is already done.

03 · A level 3 goal for a new page

Swap the paths for the ones in your project. Anything between less-than and greater-than signs is for you to fill in.

goal.md (adapted from the Execução Longa kit)
# Goal — new page: <slug>

## Result
The page /<slug>/ ready for gate 2, without breaking the rest of the site.

## Done criteria (command → expected output)
**Function**
- [ ] grep -c '<h1' dist/<slug>/index.html → 1
- [ ] grep -o 'rel="canonical" href="[^"]*"' dist/<slug>/index.html → https://www.seusite.com/<slug>/
- [ ] grep -c 'application/ld+json' dist/<slug>/index.html → 1 or more

**Regression**
- [ ] npm test && npm run build → no errors

**Limit**
- [ ] git diff --stat -- tests/ docs/CHECKLIST.md → empty
- [ ] git status --porcelain → only the new page and the 2–3 pages of the link ladder

## Human gate (the command does not prove it)
- first-hand data with a link to the evidence (checklist 2)
- human reading: opinion, what went wrong, the author's voice (checklist 9)
- swap test (checklist 10)

## Constraints
- through the subscription only; no API without authorization
- no push: the push is mine, after the gate
Loop request (/goal in Claude Code)
/goal The terminal output shows each command from goal.md with the expected output, and goal.md has all criteria checked off. Do not push. When you finish, stop and show me the diff.
Simulation: illustrative example
  • 0 vague: "improve the new page".
  • 1 subjective: "page reviewed and clean" (the agent approves itself).
  • 2 gameable: "build with 0 failures" (you can delete the test).
  • 3 protected: build without errors and tests untouched and one H1 and canonical equal to the URL.
  • 4 independent: level 3 + you at gate 2 reading as a reader.
  • Words like good, clean, adequate, complete.
  • Depends on the agent saying it is done.
  • Only a count, with no check of the content.
  • Does not say what must not change.

04 · Practice: one page through the loop and the gate

Use a new page (or a rewrite) from your site.

S1 · The goal.md

30 min

Write the page's goal.md with at least one function criterion, one regression criterion, and one limit criterion, and run the five questions on each one.

Done when: each criterion has a command and the expected output, there is at least one check (a frozen file or a count with content) and the human gate section lists what the command does not prove.

S2 · Loop and gate

40 min

Run the agent with the loop request. When it stops, read the page as a reader, decide, and only then do the push yourself.

Done when: the conversation shows each command with the expected output, goal.md has your gate 2 approval with a date, and the push went out after it.
